## 2. 输入格式详解 · Input Format 🔴

**数据来源**：竞彩赔率取自 **中国体育彩票官方网站**（<https://www.lottery.gov.cn/jc/index.html>）的**每日公开数据** —— 赛前多次抄录同场赛事即可形成"变动序列"。本项目**仅作研究引用**（不涉及非授权获取、不进行再分发），详见 [DISCLAIMER.md](../DISCLAIMER.md) §4.5。

模型的输入 = **一个纯文本赔率文件**（竞彩赔率变动序列）。最小可用格式：

```
赛事：某某联赛 主队(主) VS 客队(客)

【胜平负】2.67,3.22,2.25 → 2.75,3.22,2.20 → 2.67,3.22,2.25
【让球+1】1.47,3.95,5.10 → 1.50,3.90,4.85 → 1.48,3.95,5.00
【总进球】13.00,5.50,4.00,... → ... → 15.00,5.90,3.30,3.40,5.45,9.50,20.00,31.00
【半全场】4.40,15.00,27.00,6.50,5.50,5.50,28.00,15.00,3.95 → ... → 4.75,14.00,27.00,6.50,5.20,5.30,28.00,14.00,4.10
【比分】1:0=10.50 2:0=14.00 2:1=9.00 ... 0:0=15.00 1:1=6.25 2:2=11.00 ... 0:1=9.50 1:2=8.00 ...
```

**格式要点**：

| 规则 | 说明 |
|:--|:--|
| `→` | 分隔**不同时间点**的赔率（至少 2 个时点才有"变动"信号） |
| `,` | 一节内的赔率用逗号分隔（顺序按玩法固定） |
| `【节名】` | 节标题；缺某一节 → 下游对应模块自动"降级/不触发"（会在输出中标注） |
| 队名 | 中文队名会做别名归一化（内置 246 队映射） |

> 💡 **时点越多越好**：变动序列是"资金流"与"形态学"分析的原料；只有一个时点时，动态类判定会自动标注"无变动"。

## 3. 跑一场完整分析 · Run One Match

### 3.1 一条命令启动预计算

```bash
python scripts/tmp/calc_all.py <你的赔率.txt> 英超 \
    --eu 1.55,4.20,6.00 \
    --handi -1 \
    --o25 1.90 --u25 2.00 \
    --elo 120 --inj_h 2 --inj_a 3
```

**参数解读**：

| 参数 | 含义 | 从哪来 |
|:--|:--|:--|
| `<txt>` | 竞彩赔率文件 | 你的输入 |
| `英超` | 联赛（中/英/代码均可） | 英超=E0=epl=premier-league |
| `--eu 主,平,客` | 欧盘胜平负**去抽水前**赔率 | 欧盘数据源（1xbet 等） |
| `--handi` | 亚盘让球（**负 = 主让**） | 亚盘盘口 |
| `--o25 / --u25` | 大小 2.5 球赔率 | 大小球盘 |
| `--elo` | 两队 ELO 差 | ClubElo 等 |
| `--inj_h / --inj_a` | 双方伤停影响分 | 伤停评估（位置×重要性） |
| `--water` | 主队水位（欧式 1.8–2.1 标度） | 亚盘水位 |

> 🔴 **`--max_h / --max_d / --max_a` 不需要传**：跨机构分歧由 `calc_all` **自动解析输入文件头**的
> 「最高价 / 最低价」行（形如 `跨机构即盘：348 家 · 最高价 3.4/3.75/2.48 · 最低价 2.72/3.0/1.65`）。
> 头部没有该行时输出 `无数据(原因)`，**不会**用单家赔率冒充跨机构。
>
> 🔴 **只有亚洲大小球线（2.5/3、3/3.5 等）时**，不要手工折算 O2.5——四分之一线是 half-win/half-loss，
> 直接当二元盘去水会系统性偏差。用专门的折算器：
>
> ```bash
> python scripts/tmp/ou_from_asia.py --line 2.75 --over 0.82 --under 0.98 --json
> # → {"lambda":3.104599,"p25_over":0.599832,"o25":1.667134,"u25":2.498948,...}
> ```
> 把输出的 `o25` / `u25` 传给 `--o25` / `--u25`。

### 3.2 输出解读（按段落）

| 输出段 | 含义 |
|:--|:--|
| `[去水]` | 抽水剥离后的三向隐含概率 |
| `[硬核]` | 方向差距 / skew / 凯利 / 反抽水比 |
| `[联赛基准]` | 该联赛大球率/平局率/本场档位实际命中率（禁凭记忆） |
| `[live 引擎]` | 多源融合后的比分概率矩阵 Top10（市场/半场/CS/泊松/盘口加权） |
| `[锚-市场一致性]` | 主锚是否落在市场**约束**内（净胜档区间 / 总进球界 / 盘口方向禁项）。越界时列出**逐条违反项**并给「约束内候选参考」；**取哪个锚由模型决定**，脚本不代定 |
| `[跨机构分歧]` | 修正35：最高价相对基准的偏离（<5% 低可信降级 / >10% 更可信） |
| `[netmargin-handi]` | 亚盘线 / 体彩让球L 双轨对照。**净胜档以亚盘线为准**；两者不一致会标「否」 |
| `[HAF / ELO / xG]` | 先行层三态。非五大联赛会标「不在覆盖域」，缺失必写原因 |
| `[锚-量级一致性]` | 锚的总进球是否与量级判定矛盾 |
| `[必核清单]` | **脚本生成的检查清单** —— 这是给 LLM 的"施工图"，逐项走完才算完整分析 |

### 3.3 手动走一遍（LLM 会做的事）

```
① 读必核清单 → ② 逐项消费脚本输出（不重算·不凭记忆）
③ 触发规则就标数值；不触发就写原因（三态标注）
④ 方向判定 → 大小球深度 → 比分锚定 → 一致性回查
⑤ 自检表逐项打勾（每项附证据）→ ⑥ 落盘存档
```

### 3.4 校验与落盘

```bash

## 4. 常见问题 · FAQ

**Q1: 没有 API key 能跑吗？**
能。外部源会标记"无数据(原因)"，模型按"三态标注"继续（只是少了交叉验证）。

**Q2: 赔率只有 1 个时点？**
动态类判定自动标"无变动"；静态结构（去水/档位/skew）照常计算。

**Q3: `--eu` 不传会怎样？**
现场比分引擎不触发（脚本会显式告警），只剩竞彩侧计算 —— **建议必传**。

**Q4: `--handi` 的符号？**
**负 = 主让**（-1 表示主让一球）；受让用正数。跟原始盘口一致。

**Q5: 输出里的"三态标注"是什么？**
`触发(数值)` / `不触发(原因)` / `无数据(原因)` —— 强制标注，禁止"没做也不说"。

**Q6: 判定和我的直觉相反？**
先看 skew：弱共识场（<150%）本来就只有 36–43% 可判性 —— 此时模型会**并列平局**而非单押，这是设计而非失误。
门限 150% 是**单一真源**（`calc_match.WEAK_SKEW_PCT`），130% 的旧写法已废弃。

**Q6b: 净胜档到底看亚盘还是体彩让球？**
**亚盘线**（`--handi`）。体彩让球 L 只有 −1/0/+1 三档粒度，仅用于让球盘去水。
输出里的 `[netmargin-handi]` 行会同时列出两个值并标一致性。

**Q6c: 脚本给的「建议锚」必须照用吗？**
不必须。那是**约束内候选参考**。脚本只负责给出约束（净胜档区间 / 总进球界 / 盘口方向禁项）
和逐条违反说明，定锚权在模型。另外 `[市场净胜期望档]` 的系数是**未回测经验公式**，
禁止和「V6 四象限 22.7 万场」同档引用。

**Q7: 能批量跑吗？**
可以——对每个 txt 分别跑 `calc_all`，然后按"批"组织（模型支持批末汇总信号）。

**Q8: 准确率多少？**
诚实回答：方向约七成（含并列口径）、比分锚命中约两三成（低分场显著更高）；**长期串关 EV 为负**。本项目价值在**方法**不在**神器**。

## 5. 故障排查 · Troubleshooting

| 症状 | 可能原因 | 解决 |
|:--|:--|:--|
| `数据不足` 假报 | txt 节标题/时间戳格式偏差 | 用标准 `【节名】` + 逗号行；或跑归一化工具（如提供） |
| 联赛基准不显示 | 传了别名且非五大 | 用中文名或标准代码（英超/西甲/E0/SP1…） |
| 外部源全 missing | 没配 key 或代理不通 | 检查 `.env`；测代理连通性 |
| `--eu` 后引擎不触发 | 参数被吞（写成 `--eu --handi`） | 每个参数后跟值：`--eu 1.55,4.20,6.00` |
| UnicodeEncodeError | Windows 控制台 GBK | `set PYTHONIOENCODING=utf-8` |
| 输出校验误报 | 术语写法不同 | 按提示补对应"块"（如"锚-市场一致性"字样） |
