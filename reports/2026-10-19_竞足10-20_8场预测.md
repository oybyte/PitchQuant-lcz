## 3. 🔴 本次跑批发现的真实 Bug：弱共识「必须并列」从未生效

### 3.1 现象

5 场弱共识场的输出**自相矛盾**：

```
方向(欧亚综合): 主胜(LOW) | 并列:no | ...
🔴🔴弱共识场(skew=121.3%<150%) → **平局必须与市场首选并列（禁单押市场首选）**
```

同一份输出里，**方向行说"并列:no"，弱共识行说"必须并列"。**

### 3.2 影响范围（实测）

| 批次 | 弱共识场 | 其中「并列=no」 |
|:--|--:|--:|
| output 79 场 | 33 | **33（100%）** |
| 竞足 59 场（本次） | 5 | **5（100%）** |
| batch_v259C | 8 | **8（100%）** |
| batch_v259V | 9 | **9（100%）** |
| batch_v259W | 17 | **17（100%）** |
| **合计** | **72** | **72（100%）** |

**这条规则在 72 场弱共识场中一次都没生效。**

### 3.3 根因

| 层 | 事实 |
|:--|:--|
| `direction_full` 形参 | **没有 skew / weak 参数** → 无法感知弱共识 |
| 并列判定 | 只看 `draw_signal`（修正53分组分 ≥1.5），与 skew 无关 |
| 弱共识规则 | 在 `calc_match` 里**只是 print 一行提示**，从未写入 `parallel` |
| `WEAK_SKEW_PCT=150` | 单一真源存在，但只被**显示层**消费 |

**性质**：与 AGENTS §6.5 记载的教训同类——**规则写了、提示打了，但从未落到判定层**。

### 3.4 后果

- 弱共识场（命中率≈随机的 36–43% 区间）被系统性地**单押**
- 用户看到的 "并列:no" 会让下游 Agent 认为可以单押
- 与项目「弱共识必须三向覆盖」的纪律直接冲突

### 3.5 已修复（2026-10-19·TDD）

**先验证方向、再改代码**（遵守 §6.5「n=2 不足以改规则」的教训）：

| 组 | 弱共识（受修复影响） | 强共识（不应变化） |
|:--|:--|:--|
| A组 442（开发集） | 43.3% → **70.9%**（+27.7pp） | 66.3% → 83.0% |
| B组 79（样本外） | 50.0% → **81.2%**（+31.2pp） | 70.2% → 85.1% |
| 合计 520 | 44.5% → **72.8%**（+28.3pp） | 66.9% → 83.3% |

**修法**：新增 `calc_v3572.weak_consensus_parallel()`（真源 `WEAK_CONSENSUS_PCT` ←
`calc_match.WEAK_SKEW_PCT`），`calc_all` 接线并输出留痕「弱共识强制并列」。

**端到端**：79 场重跑后弱共识并列率 **0% → 100%**；模型 any 口径 62.0% → **74.7%**。
**守线**：`tests/test_weak_consensus_parallel.py`（7 项）。全套 **384 passed**。
