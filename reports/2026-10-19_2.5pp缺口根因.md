## 0. 结论

**根因：`prob_calibration.json` 的 `0.30-0.40` 档给主胜 −5.97pp 的修正，而该档的偏差 p=0.114 不显著、四个批次正负颠倒，纯属噪声。**

它把「主胜领先但主客接近」的场次直接压成客胜。修复后 79 场从 **59.5% → 62.0%**，改判 5 场 → 0 场。

## 4. Phase 4 · 修复

### 4.1 改动

`scripts/tmp/build_prob_calibration.py` 增加显著性门：

```python
ALPHA = 0.05
pv = _pvalue(k, n, mid)          # 双侧二项检验
if pv >= ALPHA:
    bias = 0.0                   # 不显著 → 不施加
```

每档写入 `p_value` 与 `raw_bias_pp`（保留原值供审计）。

### 4.2 为什么不「一刀切全关」

`0.60-0.70` 档 p=0.036 显著且 +11.9pp，是真实的「热门低估」效应——
关掉它会丢失真信号。**显著性门是这个问题的正解，不是保守主义。**

### 4.3 效果

| 指标 | 修复前 | 修复后 |
|:--|--:|--:|
| 模型方向 | 59.5% | **62.0%** |
| 与市场差距 | −2.5pp | **0.0pp** |
| 改判场次 | 5（全错） | **0** |

## 5. 测试

新增 `tests/test_prob_calibration_validity.py`（6 项）：

1. 每档必须带 `p_value`（无 p 值 = 无法区分真偏差与噪声）
2. `p>=0.05` 的档 `bias_pp` 必须为 0
3. 引发本次缺口的 `0.30-0.40` 档必须为 0
4. 唯一显著档 `0.60-0.70` 必须保留（防一刀切）
5. 区间仍连续覆盖 0-1（读端 `if lo<=ph<hi`）
6. **端到端**：校准不得把「市场主胜、主客接近」的场次翻成客胜

另修正 2 项因设计变更而失效的过时断言（`test_output_observability` 原假设「校准后对照值恒出现」，现该值仅在显著档出现）。

**371 → 377 passed。**

## 6. 教训

> **「校准」不等于「加一个偏差」。** 没有显著性检验的偏差修正，等于把噪声固化成模型的一部分。
> 本次 −5.97pp 从 441 场样本里算出来看着很权威，实际 p=0.114、四批次正负颠倒。

这条与 AGENTS §6.5 记的「n=2 不足以支持规则变更」是同一句：**样本量够不够，要看显著性，不是看绝对数。**
